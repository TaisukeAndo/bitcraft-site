# GAS自動返信の設計方針とセットアップ手順

## トリガーの選び方: スプレッドシート紐付けを標準にする

GASでGoogleフォーム送信をフックする方法は2通りある。

1. **フォーム自体にスクリプトを紐付ける**（Googleフォームの「⋮」メニュー→「スクリプトエディタ」）
2. **回答先スプレッドシートにスクリプトを紐付ける**（スプレッドシートの「拡張機能」→「Apps Script」）

このSkillでは**2番目（スプレッドシート紐付け）を標準**として案内する。理由は、フォーム側のスクリプトエディタ入口はUIの奥まった場所にあり見つけにくいのに対し、スプレッドシートの「拡張機能」メニューは常に見えており、bitcraftのユーザー層（非エンジニアも含む）にとって迷いにくいため。加えてスプレッドシートに紐付けたインストール型トリガーは `e.namedValues` で「質問タイトル→回答」のマップをそのまま受け取れるので、コード側で列位置を数える必要がない。

## セットアップ手順（ユーザーに提示する完全版）

1. Googleフォームを作成する。**各質問のタイトル文言は、サイト側フォームの入力ラベルと一字一句完全に一致させる**（全角/半角、句読点、末尾の「？」の有無まで揃える）。ここがずれるとGASが回答を拾えず、自動返信が静かに送られなくなる（エラーにもならないので気づきにくい）。
2. フォームの「回答」タブを開き、右上の緑のスプレッドシートアイコンから「新しいスプレッドシートを作成」を選ぶ。これで回答が書き込まれる専用シートができる。
3. 作成されたスプレッドシートを開き、メニューの「拡張機能」→「Apps Script」を選ぶ。エディタが開いたら、デフォルトで入っている `Code.gs` の中身をこのSkillが生成したコードで**丸ごと置き換えて**保存する（Ctrl/Cmd+S）。
4. エディタ左側の時計アイコン（トリガー）を開き、「トリガーを追加」を押す。以下の内容で設定して保存する:
   - 実行する関数を選択: `onFormSubmit`
   - イベントのソースを選択: `スプレッドシートから`
   - イベントの種類を選択: `フォーム送信時`
5. 保存すると初回だけGoogleの権限承認画面が出る。自分（またはbitcraftの管理アカウント）で作成したスクリプトなので、「詳細」→「（プロジェクト名）に移動」と進んで許可してよい。ここで許可しないとメールは一切送信されない。
6. サイト側フォームがまだ `entry.xxxxxxxxx` をプレースホルダーのまま保留していた場合、Googleフォームの「⋮」→「事前入力したリンクを取得」機能で各質問のIDを確認し、`apply-script.js` の `GOOGLE_FORM_URL` と各 `name` 属性に反映する（`add-seminar` Skillの `references/google-form-fields.md` と同じ手順）。
7. Googleフォームを実際に1件テスト送信し、(a) スプレッドシートに回答行が追加されること、(b) 入力したメールアドレス宛に自動返信が届くことの両方を確認する。届かない場合は次の「トラブルシューティング」を見る。

## Code.gs を書くときの実装方針

- `e.namedValues` はキーが質問タイトル、値が「回答の配列（通常1件）」のオブジェクト。チェックボックスのように複数選択できる質問は配列の1要素にカンマ区切り文字列として入ることが多いので、そのまま文字列として扱えば十分（分割して個別処理する必要は基本無い）。
- 宛先メールアドレスの質問タイトルに対応する値が空だった場合は、**黙って握りつぶさず** `console.error` などでログに残し、関数を早期リターンする。GASの実行ログ（実行数）から後で気づけるようにするため。
- `MailApp.sendEmail(recipient, subject, body, options)` を使う。`options.name` で表示上の差出人名を変えられるが、**実際の送信元メールアドレスは、このスクリプトを承認したGoogleアカウント自身になる**（Workspaceでエイリアスを登録していない限り、任意のアドレスに変更することはできない）。この制約は必ずユーザーに伝える。
- CCが必要な場合は `options.cc`、返信先を送信者と別にしたい場合は `options.replyTo` を使う。
- `GmailApp.sendEmail` でも同等のことができるが、`MailApp` の方がクォータ管理がシンプルで用途に対して過不足ない。署名やHTMLメールが必要になったら `options.htmlBody` を追加する程度に留め、複雑なテンプレートエンジンは持ち込まない（このリポジトリ全体がビルドツール無しの素朴な構成であることに合わせる）。

## 送信クォータ

`MailApp.sendEmail` の1日あたりの送信数には上限がある（無料のGoogleアカウントで1日100通程度、Google Workspaceアカウントでプランに応じて1,500通程度）。bitcraftのセミナー規模（定員20名程度）であれば通常問題にならないが、上限に達すると `Service invoked too many times` のようなエラーで以降の送信が失敗する。想定申込数が多いフォームを作る場合は事前にユーザーへ触れておく。

## トラブルシューティング

- **メールが届かない・トリガーは動いているのにログにエラーも出ていない**: 質問タイトルの表記ゆれを最初に疑う。`Logger.log(JSON.stringify(e.namedValues))` を一時的に入れて実行し、実際のキー名を確認するのが最速。
- **トリガー自体が発火しない**: スプレッドシートではなくフォーム側に別のスクリプトが紐付いていないか、トリガーの「イベントのソース」が「スプレッドシートから」になっているか確認する。
- **権限エラーで止まる**: トリガー保存時の認可をスキップしていないか確認する。認可をやり直すには一度トリガーを削除して再作成すると出し直せる。
