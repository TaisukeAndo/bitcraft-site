# 申込みフォーム（Googleフォーム）の扱い

申込ページ（`apply/index.html`）は Google フォームへ直接 POST する仕組みになっている。`apply-script.js` の `GOOGLE_FORM_URL` に `.../formResponse` エンドポイントを指定し、各 `<input>`/`<textarea>`/`<label>` の `name` 属性に Google フォーム側の質問ID（`entry.xxxxxxxxx`）を対応させている。

このSkillは Google フォームそのものを新規作成できない（別Skillの領域、とユーザーと合意済み）。そのため、必ず以下のどちらかで進める。

## パターンA: ユーザーが既にGoogleフォームを作成済み

ユーザーに次を確認する:
- フォームの回答送信用URL（フォーム編集画面で「事前入力したURLを取得」→生成されたURLの `viewform` を `formResponse` に置き換えたもの、または開発者ツールでフォーム送信時のリクエスト先を確認したもの）
- 各質問に対応する `entry.xxxxxxxxx` の値（フォームの「事前入力したリンクを取得」機能を使うと、質問ごとに割り当てられたIDがURLパラメータとして確認できる）

集められた対応関係で `apply-script.js` の `GOOGLE_FORM_URL` と `apply/index.html` の各 `name` 属性を書き換える。

## パターンB: Googleフォームがまだ無い

以下で進めてよい。ユーザーには「フォームが未接続なので、フォームを作成後に entry ID を教えてもらえれば反映する」と明示すること。

- `apply-script.js` の `GOOGLE_FORM_URL` には `"TODO: Googleフォームの formResponse URL をここに設定してください"` のような、実行時に明らかに動かないと分かる文字列を入れる（黙って動くように見せかけない）
- `apply/index.html` 側の `name` 属性は元テンプレートの `entry.xxxxxxxxx` をそのまま残しておいて構わない（後で対応するフォームを作った際に、質問文と項目数さえ揃っていれば entry ID だけ置換すれば済むようにするため）

## フォームの質問構成をどこまで引き継ぐか

`claude-code-1day` の申込フォームは「基本情報」「AI活用状況」「業務・ツール環境」「セミナーへの期待」「同意」の5ブロックで構成されている。このうち以下は**ほぼ全セミナー共通で残すべき**基本情報:

- お名前・メールアドレス・電話番号
- ご職業・ご所属
- プライバシーポリシーへの同意（必須チェックボックス）

一方で「AI活用状況」「会計・請求管理に利用しているサービス」「Googleのサービスで業務利用しているもの」のようなブロックは Claude Code セミナー特有のヒアリング項目なので、新しいセミナーのテーマに合わせて質問内容を作り直す（テーマに関係ない項目をそのまま使い回さない）。「このセミナーで最も解決したい課題」のような期待値ヒアリングの枠組み自体は汎用的なので流用しやすい。
