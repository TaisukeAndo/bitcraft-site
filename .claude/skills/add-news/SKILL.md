# お知らせ(News)記事の追加

## なぜこの手順が必要か

`news/` はビルドツールを持たない素朴な静的サイトの一部で、「お知らせ」は3箇所に同時に存在する: (1) トップページ `index.html` の `#news` セクションにある簡易一覧、(2) `/news/` の全件一覧ページ、(3) 記事ごとの詳細ページ `news/<slug>/index.html`。この3つはテンプレート共通化の仕組みが無いためHTMLとして独立しており、どれか1つだけ更新すると「トップページでは見えるのに詳細を開くとリンク切れ」「一覧には無いのにトップには残っている」といった不整合がすぐに起きる。このSkillは、この3箇所を毎回セットで正しく更新するためのものである。

`news/news-detail-style.css` は記事詳細ページ用に既に用意されているが、まだ実例が無い（最初のニュースが0件のため）。このSkillが初めて実例を作ることになるので、CSSのクラス名（`.top--news` `.article-meta` `.detail` `.back-link` 等）と一致するマークアップを毎回正確に再現することが特に重要になる。

## 全体の流れ

1. 必要な情報をユーザーから集める
2. 今日の日付を確認する
3. slugを決める
4. 記事詳細ページ（`news/<slug>/index.html`）をテンプレートから生成する
5. `/news/` の一覧ページに記事を追加する
6. トップページの `#news` セクションに記事を追加する（コンパクト表示・最新3件まで）
7. 最終チェック

順番に説明する。

## ステップ0: 情報収集

いきなり書き始めず、以下が揃っているか確認する。ユーザーが最初のメッセージで既に書いてくれている項目は聞き直さない。

- **タイトル**: 一覧の見出し・詳細ページの `<h1>` に使う短い文（例:「Claude Code AIエージェント構築1Dayセミナー、申込受付を開始しました」）
- **掲載日**: 基本は本日の日付（ステップ1で確認）。過去の出来事を後から記録する場合はユーザー指定日を使う
- **タグ**: 一覧に表示する短いラベル。自由記述でよく、迷ったら「セミナー」「サービス」「お知らせ」「メディア」あたりが実例として自然
- **一覧ページ用の概要文**: `/news/` の一覧にだけ表示される1〜2文（トップページのコンパクト表示には出さない）
- **詳細ページの本文**: 見出し(`h2`)・段落・箇条書きで構成する記事本体。何を伝えたいお知らせなのかによって長さも構成も変わってよい（セミナー募集開始なら「開催概要の要約＋申込みページへのCTAリンク」、休業案内なら期間と理由の説明、というように内容に応じて自然に組み立てる）
- **関連ページ**: このお知らせが何か既存のページ（セミナー詳細ページ、サービスページ等）についてのものなら、そのURL。本文中の内部リンクや文末のCTAボタンに使う
- **slug**: フォルダ名にする英語kebab-case（例: `ai-agent-1day-open`）。ユーザーが指定しなければ内容から提案し、確認を挟まず先に進めてよい

情報が全部揃うまで待つ必要はない。埋まっていない部分は「詳細は近日公開」のようなプレースホルダーで仮置きし、ユーザーへの最終報告で明示すればよい。

## ステップ1: 今日の日付を確認する

```bash
date +%F
```

会話の中で「今日の日付」が示されていても実行環境のタイムゾーンとズレることがあるため、判断の基準にするのは常にこのコマンドの出力にする。

## ステップ2: slugを決める

`news/<slug>/` というディレクトリを新規に作る。他のニュース記事や `service/seminar/<slug>/` と衝突しない、内容が分かる英語kebab-caseにする。日付を含める必要はない（掲載順は記事の内容ではなく一覧ページ側のHTML上の並び順で管理するため）。

## ステップ3: 記事詳細ページを生成する

```bash
mkdir -p news/<slug>
cp .claude/skills/add-news/assets/detail-template.html news/<slug>/index.html
```

テンプレートには `{{TITLE}}` `{{DESCRIPTION}}` `{{KEYWORDS}}` `{{SLUG}}` `{{TAG}}` `{{DATE_DISPLAY}}` `{{BODY}}` というプレースホルダーが埋め込まれているので、すべて実際の内容に置き換える:

- `{{TITLE}}`: `<title>`・`og:title`・`<h1>` の3箇所（同一テンプレート内に複数出現するので取りこぼさない）
- `{{DESCRIPTION}}`: `meta description` と `og:description` の2箇所。ステップ0の概要文、無ければ本文の要約を1〜2文で
- `{{KEYWORDS}}`: `meta keywords` に足すカンマ区切りのキーワード（固定の `bitcraft,お知らせ,News,...,安藤太亮` に差し込む形）
- `{{SLUG}}`: `og:url` に使う（ステップ2で決めたslugと一致させる）
- `{{TAG}}` / `{{DATE_DISPLAY}}`: 本文冒頭の `.article-meta` に表示される。`{{DATE_DISPLAY}}` は `2026.08.15` のようにドット区切りで統一する（他ページの日付表記に合わせる）
- `{{BODY}}`: 記事本文。`<h2>` 見出し・`<p>` 段落・`<ul><li>` 箇条書きを自由に組み合わせて書く（`policy/index.html` が同じ `.detail > .content` 構造の実例なので、書き方に迷ったら参考にしてよい）。関連ページへのCTAが要る場合は `<p><a href="...">詳細・お申込みはこちら</a></p>` のような形で本文末尾に置く（相対パスの深さに注意。`news/<slug>/` からは `../../` がサイトルート）

`<link rel="stylesheet" href="../news-detail-style.css">` や `../../js/script.js` のようなパス階層はテンプレートのままで変更不要（`news/<slug>/` は常にルートから2階層目）。

## ステップ4: `/news/` 一覧ページに記事を追加する

`news/index.html` の `<ul class="news-list">` の**先頭**（新しい順に並べる）に、以下の形で `<li>` を追加する:

```html
<li class="news-item">
    <a class="news-item-link" href="./<slug>/">
        <span class="news-date">{{DATE_DISPLAY}}</span>
        <span class="news-tag">{{TAG}}</span>
        <span class="news-item-title">{{TITLE}}</span>
        <i class="fa-solid fa-chevron-right"></i>
    </a>
    <p class="news-item-desc">{{一覧ページ用の概要文}}</p>
</li>
```

`<li class="news-item news-empty">現在、お知らせはございません。</li>` が残っていれば、これが最初の記事なので削除する。

## ステップ5: トップページの `#news` セクションに記事を追加する

`index.html` の `<div class="news" id="news">` 内 `<ul class="news-list">` にも、同じ記事を**コンパクト版**（`news-item-desc` は付けない）で追加する:

```html
<li class="news-item">
    <a class="news-item-link" href="/news/<slug>/">
        <span class="news-date">{{DATE_DISPLAY}}</span>
        <span class="news-tag">{{TAG}}</span>
        <span class="news-item-title">{{TITLE}}</span>
        <i class="fa-solid fa-chevron-right"></i>
    </a>
</li>
```

トップページのリンクは他の主要導線（`/contact` や `/news/` 自体）と同じくルート相対パス（`/news/<slug>/`）で書く。`news/index.html` 側の `./<slug>/` とはパスの書き方が違う点に注意する（ディレクトリの深さが違うので当然だが、コピペで一覧側と混同しやすい）。

`news-empty` が残っていれば削除する。

**トップページは最新3件までに保つ**（デザイン上コンパクトな一覧である想定のため）。追加した結果 `news-item`（`news-empty`を除く）が4件以上になる場合は、一番古い1件を**トップページ側の `<li>` からだけ**削除する。`/news/` 側とその記事の詳細ページは削除しない（全件の記録はあくまで `/news/` が正なので、トップページから消えても記事自体は残り続ける）。

## ステップ6: 最終チェック

```bash
bash .claude/skills/add-news/scripts/check_news.sh <slug>
```

以下を機械的に確認する:
- テンプレート変数 `{{...}}` の置換漏れ
- 詳細ページ・一覧ページ・トップページ間の相対リンクが実在するファイルを指しているか
- `/news/` とトップページ双方に新記事へのリンクがあるか
- `news-empty` プレースホルダーの消し忘れ
- トップページのコンパクト一覧が3件を超えていないか

スクリプトが指摘した項目は必ず目視でも確認する（自動チェックは機械的に分かるものしか見つけられず、文章の質やレイアウト崩れ、日付・タグの表記ゆれは見ていない）。

最後に、可能であればブラウザ相当の確認（各HTMLファイルを開いてリンク遷移を目でたどる）をして、ユーザーに「トップページの見え方」「一覧ページの見え方」「詳細ページの内容」を要約して報告する。

このリポジトリで変更をコミット・PR化する流れは `create-pr` Skill が別途あるので、ユーザーがそれを望んだらそちらに任せる（このSkillの範囲はファイルの作成・編集まで）。
