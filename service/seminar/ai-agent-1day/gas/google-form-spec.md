# Googleフォーム質問仕様書（コピペ用）

`apply/index.html` の申込フォームに対応する、実際に作成すべきGoogleフォームの質問一覧。上から順にGoogleフォームの編集画面へそのまま入力していけば完成する。

**重要: 質問タイトルは一字一句このとおりに入力すること。** 特に「お名前」「メールアドレス」の2つは `gas/Code.gs` の `CONFIG.NAME_FIELD` / `CONFIG.EMAIL_FIELD` が文字列一致で参照しており、全角/半角・句読点・表記が1文字でもずれると自動返信メールが静かに送信されなくなる（エラーにもならないため気づきにくい）。

作成後にやること: 各質問の「⋮」→「事前入力したリンクを取得」で `entry.xxxxxxxxx` を確認し、`apply/index.html` の対応する `name` 属性と `apply/apply-script.js` の `GOOGLE_FORM_URL` に反映する。

**→ 対応済み。** 実際のGoogleフォーム（<https://docs.google.com/forms/d/e/1FAIpQLScDbru2yfQwWov5n5heSOexj0-xeDSZMldRmxB8Dw7Mh9poHw/viewform>）のentry IDを `apply/index.html` と `apply/apply-script.js` に反映済み。ただし「お名前」の質問タイトルが `gas/Code.gs` の `CONFIG.NAME_FIELD`（"お名前"）と一字一句一致しているかは、Googleフォームの編集画面で目視確認すること（本仕様書どおりに作成されていれば問題ないはずだが、GAS設置前に必ず確認する）。

**5・7・9の「その他」設定を要修正:** 実際にテスト送信したところ、この3問で「その他」の自由記述を入力すると `400 Bad Request` になる不具合が見つかった。原因と対処は下記の各質問の項目、および本ファイル末尾の「既知の問題」を参照。Googleフォーム側で該当3問の **「'その他' を追加」トグルをOFFにし**、選択肢として手入力で「その他」を追加し直す作業が必要（entry IDは変わらないのでそのままでよい）。

**「その他」を選択できる質問（5・7・9）について（重要・要修正）:** 当初はGoogleフォーム標準の **「'その他' を追加」** トグルを使う想定だったが、実際にサイト経由でテスト送信したところ `400 Bad Request` になることを確認した。原因は、この機能が内部的に要求する送信フォーマット（`entry.xxxxxxxxx=__other_option__` と、末尾に `.other_option_response` を付けた別フィールド）を外部から直接POSTする際に正しく再現できなかったため（実際のGoogleフォームUIを経由しないと成立しない可能性が高い）。

そのため、この3問は **「'その他' を追加」トグルはOFFのまま**、選択肢の1つとして手入力で「その他」を追加する（他の選択肢と同じ扱い）。自由記述欄はサイト側だけの機能で、「その他」が選ばれていれば送信直前にJS（`apply-script.js` の `applyOtherValues()`）がその選択肢自体の送信値を自由記述の内容に書き換えてから送信する。Googleフォーム側は最初から関知しないため、この3問のentry IDは他の通常の選択式質問と同様に1個だけで良い（`.other_option_response` のような別IDは不要）。

## 既知の問題: Googleフォーム標準の「その他」機能は使わない

**症状:** 「ご職業・ご所属」「現在利用しているAIツール」「社内で自動化・効率化したい業務領域」のいずれかで「その他」を選び自由記述を入力してテスト送信すると、`POST .../formResponse` が `400 Bad Request` になる（他の項目だけの送信は成功する）。

**原因（推定）:** Googleフォーム標準の「'その他' を追加」機能は、フォームを開いてブラウザで直接回答する場合に限り動く内部フォーマット（`entry.xxxxxxxxx=__other_option__` と、対になる自由記述用の別フィールド）を前提にしている。このリポジトリの申込フォームは `contact/` や他セミナーと同じく、独自HTMLから `fetch(..., { mode: "no-cors" })` で `formResponse` エンドポイントへ直接POSTする方式（CLAUDE.md参照）だが、この別フィールドの正しいIDや形式を外部から特定する手段が無く、推測で組んだ値では受理されなかった。

**対処:** 該当3問はGoogleフォーム編集画面で「'その他' を追加」トグルを **OFF** にし、「その他」を選択肢の1つとして手入力で追加する（他の選択肢と全く同じ普通の項目として扱う）。サイト側の自由記述欄はGoogleフォームには存在しないサイト独自のUIとして扱い、`apply-script.js` の `applyOtherValues()` が送信直前に「その他」の選択値そのものを自由記述の内容に書き換えてから送信する。この方式であれば、既に本番で問題なく動いている他の「その他」選択肢（`claude-code-1day` 申込フォームなど）と全く同じ形の送信になるため確実。
